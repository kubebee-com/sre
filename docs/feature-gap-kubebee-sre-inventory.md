# KubeBee SRE Feature Inventory

This is the source-of-truth inventory for the current KubeBee SRE implementation used by the K8sGPT feature-gap table. It records behavior that is actually reachable from `cmd/sre-agent/main.go`, the HTTP API, or the deployment manifests. README claims are treated as claims until backed by code or tests.

Status vocabulary used by the aggregate comparison:

- `Parity candidate`: functionality that should be compared directly with K8sGPT.
- `Stronger differentiator`: KubeBee behavior that is intentionally beyond K8sGPT or provides a safer operating model.
- `Partial`: the headline exists, but important behavior, coverage, persistence, safety, or operational controls are absent.

## README Claim Audit

The README accurately identifies the major product surfaces: proactive scanning, 14 analyzer metadata entries, multi-provider triage, deterministic fallback, cleanup, approval proposals, web UI, and webhook notifications. The following claims are materially broader than the source:

1. “Full K8sGPT-compatible analyzers” is not demonstrated by compatibility tests or K8sGPT analyzer contracts. Several analyzers are simplified status checks, and the README’s specific claims for CronJob validation, Service port mismatch, Ingress class, PV states, and node network degradation are not implemented (`KB-ANL-007` through `KB-ANL-012`).
2. “All remediation actions execute strictly with explicit human permission” applies to proposal executor actions, but cleanup `POST /api/clean/pods` directly deletes pods without a proposal (`KB-HYG-002`).
3. “Interactive conversation” is a request/response Explain call, not a persisted multi-turn conversation (`KB-AI-005`).
4. “GitOpsPR” generates a text proposal only; it does not create or validate a Git pull request (`KB-REM-003`).
5. “Microsoft Teams Adaptive MessageCards” is implemented as a legacy MessageCard payload selected by `office.com` URL substring (`KB-NOT-001`).
6. “IngressAnalyzer” metadata says missing ingress class, but the implementation does not check it (`KB-ANL-009`).

## Evidence Baseline

At inventory time, source tests cover only the focused packages listed under `KB-TEST-001`. The inventory intentionally treats untested behavior as source-observed but not production-proven. The aggregate gap report should require contract tests and security controls before declaring a K8sGPT capability `Covered`, even where KubeBee has a similarly named analyzer.
