# P1 Parity Implementation Plan

> **For the implementation agent:** Execute this plan with `subagent-driven-development`. Each task is test-first, uses an existing proven library when one fits, has a disjoint write scope, and is reviewed before the next dependent task.

**Goal:** Close the parity-critical P1 gaps in the feature-gap report while preserving the P0 authentication, redaction, approval, and deployment contracts.

**Approach:** Keep the existing HTTP server and scanner usable as libraries. Add versioned contracts around them instead of replacing working code. Use client-go selectors/context, Cobra for the CLI, `robfig/cron/v3` for schedule validation, Gateway API typed clients, `crypto/aes` for local encrypted cache, and `google.golang.org/grpc` only for a narrowly authenticated compatibility boundary. Every public projection passes through the existing sanitizer.

## Task 1: Scan Plan And Analyzer Contract

**Files:**
- Create `pkg/scanplan/{plan,plan_test}.go`.
- Create `pkg/scanner/contract.go`, `pkg/scanner/contract_test.go`, and `pkg/scanner/history.go` with tests.
- Modify `pkg/scanner/scanner.go`, `pkg/scanner/types.go`, `pkg/config/config.go`, and focused server/config tests.

**Behavior:**
- Define a versioned `ScanPlan` with namespace include/exclude, label selector, kind/name selection, enabled analyzers, max concurrency, timeout, and effective-scope output.
- Validate selectors and analyzer names before any Kubernetes request; preserve the legacy `Scan(ctx, namespace)` default.
- Register existing analyzers behind a common `Analyzer` contract exposing name/resource/docs/parent metadata, context-aware analysis, and execution metrics.
- Execute selected analyzers with bounded concurrency and cancellation, retain per-analyzer errors as explicit status, and sort findings deterministically.
- Add a file-backed bounded scan history with issue fingerprints, first/last seen, resolved state, and schema version; do not store unsanitized evidence.

**Acceptance:** fake client tests cover filters, cancellation, forbidden resources, deterministic order, analyzer errors, history restart, and concurrent scans.

## Integration Verification

After every task run its focused tests. Before declaring the roadmap complete run:

1. `gofmt -w` on changed Go files, `go test -count=1 ./...`, `go test -race -count=1 ./...`, and `go vet ./...`.
2. `scripts/ci/check-manifests.sh`, `scripts/ci/check-image-metadata.sh`, shell syntax checks, `kubectl kustomize deploy/k8s`, and Docker build/metadata inspection.
3. `make kind-test` against a uniquely named disposable Kind cluster; preserve the existing cluster and capture rollout, health, readiness, auth rejection, and authenticated status evidence.
4. Search for wildcard CORS, raw secret fields, caller-controlled actors, force-delete fallbacks, floating image tags, unbounded provider responses, and unauthenticated mutation paths.
5. Run a fresh spec review and quality review after each implementation task; address findings before proceeding.
