# K8sGPT Capability Inventory

This is the normalized upstream inventory for the KubeBee SRE feature-gap table. It is based on the shallow clone at commit `731a6c90749e8e62b9325e41712c39c0d72510c4` (2026-09-01), and cross-checked against the file-by-file review in [`docs/k8sgpt-analysis/REPORT.md`](k8sgpt-analysis/REPORT.md). `Reachability` identifies a test, command, chart value, or registration path that proves the feature is intended to be usable. `Limitations` records behavior that KubeBee SRE must either reproduce deliberately or improve explicitly.

Status in the comparison document is assigned against the KubeBee SRE inventory, not here. Each `KG-*` ID is a distinct parity slice. A row may cite several related source files, but it represents one externally meaningful capability.

## Inventory Accounting

The inventory contains 45 distinct `KG-*` slices across six families: 7 CLI/analysis, 12 analyzer, 9 AI, 4 cache/privacy, 6 API/extension, and 7 integration/operations/delivery rows (the final family includes the three `KG-INT-*` and four `KG-OPS-*` rows shown above). The feature-gap table must map every row to one or more `KB-*` entries and must explain any `Partial` status with a concrete missing behavior. A KubeBee feature that is stronger than upstream should be marked as a superseding implementation only when its acceptance test covers the upstream contract and the improved safety/operability contract.
