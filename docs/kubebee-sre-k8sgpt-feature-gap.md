# KubeBee SRE to K8sGPT Feature-Gap Table

## Executive Summary

This report compares KubeBee SRE with the official K8sGPT shallow clone at commit `731a6c90749e8e62b9325e41712c39c0d72510c4` (2026-09-01). The comparison is feature-oriented rather than package-oriented: the 45 upstream capability slices are split by resource kind, provider family, transport, cache backend, extension contract, and operational behavior so a broad label cannot conceal a missing implementation.

The current strict baseline is **0 Covered, 24 Partial, and 21 Missing** upstream capability slices. `Partial` means KubeBee SRE has a meaningful analogue but lacks one or more explicitly listed behaviors, resource kinds, lifecycle guarantees, or controls. `Missing` means no usable equivalent is present. This is a gap assessment, not a claim that KubeBee SRE is unusable: KubeBee already has a proactive scan loop, 14 analyzer metadata entries, multi-LLM triage, deterministic offline fallback, approval-gated remediation, pod cleanup, multi-channel notifications, a dashboard, and chat. Those are tracked separately as stronger product capabilities and do not mask missing K8sGPT parity.

The target for 100% parity is: every `KG-*` row becomes `Covered`, or is explicitly superseded by a safer end-to-end KubeBee SRE implementation whose acceptance evidence covers the upstream contract and the improved security/operability contract. Copying K8sGPT's unauthenticated transports, wildcard RBAC, or unsafe lifecycle behavior is not an acceptable closure strategy.

## Status And Evidence Rules

- `Covered`: same user-facing outcome, reachable implementation, relevant inputs/outputs, error behavior, and lifecycle/security contract are evidenced.
- `Partial`: an implemented analogue exists; every material missing slice is named in the table.
- `Missing`: no usable KubeBee SRE implementation or equivalent exists.
- Evidence paths are source paths in either repository. Inventory IDs provide the complete per-capability evidence and acceptance detail; this table adds the cross-repository decision.
- README statements are treated as claims until source-backed. Live-cluster, cloud-provider, and external-model behavior is called out as an acceptance prerequisite rather than assumed.

The complete source inventories are [K8sGPT capability inventory](feature-gap-k8sgpt-inventory.md), [KubeBee SRE capability inventory](feature-gap-kubebee-sre-inventory.md), and the [266-file K8sGPT audit](k8sgpt-analysis/REPORT.md).

## Top Safety Blockers

1. **P0 transport and identity:** KubeBee's wildcard CORS and unauthenticated API/approval/config/cleanup routes must be protected before exposing the Ingress or service. This is the KubeBee analogue of the upstream unauthenticated gRPC/MCP risk.
2. **P0 mutation authorization:** direct pod cleanup is outside the proposal workflow, and approval actor identity is caller-controlled. Add authentication, authorization, policy checks, audit records, and approval preconditions.
3. **P0 redaction:** enforce one sanitized finding type before provider, cache, webhook, API, UI, and dump sinks; never serialize original values.
4. **P0 supply chain:** remove credentialed PR build paths, align Go versions/build args, and add SBOM/signing/provenance gates.
5. **P1 parity correctness:** implement selectors, EndpointSlice/StorageClass/PV, ConfigMap/webhook/security/Gateway/OLM analyzers and contract tests before calling analyzer parity complete.

## Assumptions And Evidence Limits

- K8sGPT evidence is frozen to the shallow clone/commit named above; upstream behavior can change after that commit and is outside this table.
- KubeBee evidence is the current working tree at analysis time. Source-backed behavior is not treated as production-proven where tests or live-cluster fixtures are absent.
- No live Kubernetes cluster, cloud account, external AI provider, Slack/Discord/Teams endpoint, or Git provider was used. Acceptance rows requiring those dependencies must run in controlled integration environments.
- The current KubeBee test suite passes for the focused packages, but the absence of analyzer/server contract tests is itself recorded as a gap. See the evidence index for exact commands and limitations.
- A stronger KubeBee feature can supersede an upstream feature only when the roadmap package records an end-to-end contract test and the feature remains safer than the upstream implementation.
